Patterns Visible in the Timeline

  • build-docs ran every day — skill refinement, code reviews, and plan authoring ran in parallel with feature work. It is the single largest consumer (13.5M effective tokens, 121 sessions); the “skill refinement” loop distilled each day’s learnings into reusable reference docs for the building-web-apps skill.
  • plan-bdd specs preceded nearly every multi-phase feature — title/sidebar/home, crop overlay, undo/redo expansion, mobile responsiveness, bottom sheet, and the two multi-touch fixes all started with a written BDD plan before the first TDD session.
  • Token intensity decayed as the codebase matured — from 5.3M effective tokens/day at the greenfield peak (Jul 5) to ~0.6–0.9M/day in the polish weeks, as change units shrank from 31-file features to targeted bug fixes.
  • Zero-commit days were plan/debug days — Jul 4–5, 20, 24–26, 30, and Aug 2 had no commits; their planning and diagnosis cost shows up in the next day’s commits (e.g., the Jul 19 pre-merge review directly produced the Jul 20–22 undo/redo expansion).
  • 233 of 517 sessions have written summaries — the remainder are subagent runs (explore, world-review, diff-review) and short sessions that were not summarized. Summary coverage skews to the build-* agents, which were required to write session summaries.
